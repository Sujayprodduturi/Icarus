## Reasoning and required implementation boundaries

The optimization is coherent: SHA blocks supply the same ordered words, a successful six-column batch has exactly the scalar map when every original word is accepted, and a rejection falls back before any bulk consumption so shifted atom boundaries cannot corrupt later rows. No estimator, finite-law probability, target, support, trial count, statistical criterion or phase budget changes. The scalar route remains necessary for custom sources/rejection semantics and therefore is not dead scaffolding.

1. **Use exact unsigned arithmetic at2^64.** For frozen denominators1,2,8,512 the acceptance limit is exactly18446744073709551616, which cannot be stored as uint64. Special-case these all-accepted denominators; never cast that limit to uint64, compare via float64, or rely on NumPy's implicit Python-int promotion. L1 gate denominator50 has limit18446744073709551600; explicitly represent that fitting threshold as uint64 and test limit-1/limit/2^64-1. Every modulus, threshold and packing operation must preserve uint64 integer semantics.
2. **Match callback state, not just callback indexes.** Baseline calls progress(0) after consuming the first six accepted atoms, then progress(65536) after that indexed row, etc. A batch must stop at those boundaries before invoking the callback. A callback that raises must leave words_consumed and the next stream word identical to scalar; it must not bulk-consume the remaining8191 rows before the first callback. Test callbacks that inspect the consumed counter and fail at both first and later boundaries.
3. **Specify ownership for peeked buffers.** A caller-visible view must not silently mutate future buffered words or become invalid when the internal buffer is compacted/refilled. Use immutable/read-only storage or bounded copies with an explicit lifetime. Count prefetched words separately from consumed words; repeated peek, partial consume, then next_word must return the unchanged suffix. Trusted fast routing should require the exact built-in stream type (custom/subclass WordSource stays scalar), not merely a next_word-shaped object.
4. **Overflow/rejection atomicity is observable.** Check the number of available counter blocks and bounded request size before hashing any new block for an unfulfillable peek. Preserve existing buffered lanes on refusal. The generator may then consume valid residual words through the scalar path and fail at the same atom/counter as before. Do not catch a general StudyError and silently treat unrelated implementation failures as a reason to redraw/retry. Per-atom1024 rejection counts and partially consumed failed-row state must match.
5. **Test the batch fallback itself.** A custom WordSource test exercises only the required scalar route. Additionally inject deterministic digest/word content into an exact CounterStream fixture so a rejection occurs inside a candidate batch, including across a row/batch edge, and compare bytes, consumed count, next word and halt reason against an independent scalar execution. Preserve immutable source snapshots when using deliberate defect tests.

The8192-date bound yields49152 words/393216 bytes, or393240 bytes with three spare lanes. Multiple masks/remainders/output arrays still require an explicit live-allocation accounting under16MiB; no whole-history six-column array for P7. The existing full output bytearray remains bounded by the declared source geometry. Keep process supervision, source binding, write/fsync/close propagation, cleanup and experimental-namespace refusal unchanged, and add NumPy's installed version to the manifest.
