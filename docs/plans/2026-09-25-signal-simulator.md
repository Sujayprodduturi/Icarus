# Task 3a Step 5 — signal-only simulator contract

**Status:** approved design, not an implemented or evaluated result. **Approved by the operator on 2026-09-25.** This narrows Step 5 of [the Task 3a plan](2026-08-22-signal-test.md); it does not authorize Steps 5b–9, real-data evaluation, a promotion verdict, or a live order path.

## Purpose and boundaries

The portfolio simulator asks whether a strategy fits a cash-, heat-, and slot-limited book. The signal simulator asks what happened to each emitted entry signal when those **portfolio constraints alone** are removed. Market constraints remain: point-in-time tradability, whole shares, the real fill model, execution costs, and the same exit ladder. A signal test is a **diagnostic**, not a deployable portfolio or an after-tax edge gate.

Inputs are one validated `StrategyCandidate`, a synthetic/already-vetted `Panel`, precomputed signal and stop columns for exactly the panel symbols, a full-source `source_indices` vector, and explicit expected signal-missingness reasons. The simulator does not evaluate the DSL, load files, write a trial ledger, access a broker, or decide what is promoted. A later runner must enforce the whole-source lockbox guard and trial ledger before using real data.

## Input and result contract

- `SignalSimulator` takes the configured `notional_inr` (currently ₹1,00,000), `CostModel`, `FillModel`, segment, and configured stale-session threshold. Its `run()` returns a frozen, slotted `SignalRunResult` with immutable `SignalTrade`, `SignalSkipped`, and `SignalMissing` tuples, an independently preflight-counted `emitted_signals` integer, and an unfilled-exit count. `SignalMissing` holds symbol, UTC decision timestamp, canonical decision index, and a `WARMUP` or `MISSING_INPUT` reason; it is not a trade refusal. The result has no equity curve, Sharpe, drawdown, tax, or gate result.
- Every signal cell must be exactly `0.0`, `1.0`, or `NaN` labelled by the caller as `WARMUP` or `MISSING_INPUT`. Missingness-map keys are canonical full-source indices, not local slice offsets; a label for local cell 1 of a slice starting at source index 40 must use key 41. An unlabelled `NaN`, infinity, finite non-binary value, missing symbol/column, wrong length, or reason attached to a finite cell is a schema error raised **before any event is simulated**. A `0.0` is no emitted entry and receives no trade/skip outcome. Labelled missingness is a separate diagnostic, not a skip.
- `source_indices` must have one nonnegative whole index per panel session, strictly increasing and contiguous. This preserves the full-source session-count meaning of `SignalTrade.holding_sessions`; a sparse index view needs a separate future contract. The panel date axis must be strictly increasing and UTC-convertible, with no repeated daily session dates. All emitted IDs and recorded events use these canonical indices, not fold-local indices.
- The source panel may include a benchmark, but Step 5 does **not** infer an intraday benchmark execution price from daily bars. All exit fragments carry `benchmark_return=None`; `SignalTrade.benchmark_return` and `pre_tax_alpha` therefore remain unavailable. A later reviewed pricing convention may change that.
- The result reconciles: independently counted emitted `1.0` cells = completed trades + explicit skips; trade and skip IDs are individually unique and disjoint; every filled entry's shares are fully represented by real exit fills and/or labelled stale marks; no position survives the last session. A repeated same-symbol signal while that symbol is open is `ALREADY_OPEN`; a fresh signal after closure may enter again. Multiple symbols have no portfolio slot/cash/heat cap.

## Event order and economics

Each panel session processes existing positions' exits first, then that session's new entry decisions. Entry from decision bar *t* is attempted only against *t+1*. A signal on the last bar is `NO_NEXT_BAR`; one outside `panel.tradable` at the decision is `NOT_TRADABLE`. Remaining candidates check already-open status, a usable next bar (`NO_EXECUTION_BAR`) and positive finite stop distance (`INVALID_STOP_DISTANCE`), whole-share sizing at the `FillModel.marketable_price`, and the actual fill (`ENTRY_NOT_FILLED` if refused). Each refusal has one deterministic reason, never a silently shrinking denominator. If more than one refusal applies, the precedence is `NO_NEXT_BAR` → `NOT_TRADABLE` → `ALREADY_OPEN` → `NO_EXECUTION_BAR` → `INVALID_STOP_DISTANCE` → `PRICE_ABOVE_NOTIONAL` → `ENTRY_NOT_FILLED`; synthetic tests pin this order.

The ₹1,00,000 is **intent**, not the return denominator. Shares are floored from intent ÷ modelled marketable buy price; a dearer share yields `PRICE_ABOVE_NOTIONAL`. Entry partial fills deploy only filled shares; deployed capital is filled quantity × filled price and equals entry-charge turnover. Charge the entry once and each filled exit fragment separately using the existing `CostModel`; return and R multiple are before capital-gains tax. A real exit on the entry bar is allowed because the protective stop was decided with the preceding entry decision. Keep the existing exit priority, trailing-stop update order, partial-fill behavior, and final-bar priority unchanged.

On a missing symbol bar, carry the open position and increment dark sessions. At the configured stale threshold, or with any residual position after the final session, mark remaining shares at the most recent traded close. The mark records both the price-source and later recognition coordinates and is explicitly **not** a fill; it still bears assumed exit charges. Exits deliberately do not consult `panel.tradable`, matching the existing portfolio simulator until the separate open finding on that asymmetry is decided.

The new `signaltest.py` may import `simcore.py`, `fills.py`, and `costmodel.py`, **not** `portfolio.py` or a broker. Do not generalise the portfolio book or share its mode-specific write-off bookkeeping.

Tests must first fail and then pass for input refusal, each skip reason, exact next-bar timing, partial entry and exit fills, trade-through, stop/target conflict, same-entry-bar stop, trailing/time/final exits, missing bars and stale marks, canonical index offsets, repeated signals, reconciliation, and stateless repeated runs. Preserve the frozen synthetic portfolio characterization unchanged. Run the focused and full unit suite, Ruff, mypy, then independent implementation and safety review. No real panel, lockbox, ledger, golden-real-data, or live path is used in Step 5.
