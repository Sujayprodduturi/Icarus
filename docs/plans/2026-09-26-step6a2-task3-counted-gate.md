# Step 6a.2 Task 3 — counted calibration and validation gate

**Status:** implementation plan; no frozen calibration or validation stream has been drawn. This refines Task 3 of [the approved Step 6a.2 plan](2026-09-26-step6a2-calibration-implementation.md), without changing its manifest, thresholds, cells, seeds, estimator or first-passing rule. Astra reviewed the architecture on 2026-09-26. No product inference or real-data evaluation is authorized.

## Outcome and safety boundary

Build an offline CLI that can produce one complete, counted, auditable synthetic calibration result and, only if that result passes and its bytes verify, one held-back validation result. A failed/incomplete attempt remains recorded and cannot be silently repeated. The existing public `generate_test_fixture_*` functions retain only the separate test seed. No public seed, `authorized` flag, resume switch, phase switch or scripted override reaches the counted-run path.

**Hold point:** this plan authorizes implementation and test-only fixtures, not the first frozen-stream draw. Commit the completed protected code, run deterministic/fixture tests and static checks, and obtain independent statistical/safety review of that exact code commit and protected blob hashes. A subsequent review-record-only documentation commit may advance HEAD; the runner records both reviewed code commit and invocation commit, requires identical protected blobs and a clean tree, and refuses any intervening non-review change. Validation has its own byte-verification gate after accepted calibration.

## Slice 1 — exclusive attempt and restricted phase context

Write failing tests for failed provenance, dirty protected files, version mismatch, reservation collision, wrong phase, closed context, scripted override, and both reserved seeds blocked before cache lookup or RNG construction. Add a private phase-scoped context that the counted runner alone creates after canonical manifest/digest/code/dependency checks and `O_CREAT|O_EXCL` artifact reservation plus fsync. Bind phase, manifest hash, protected blob hashes, dependency versions, attempt ID, start UTC, and artifact handle. Close/invalidate it on every exit. Factor shared DGP equations behind a private draw-provider interface; fixtures and counted runs use the same equations, while only the counted provider derives the reserved seed internally from the verified manifest and active context. A calibration context cannot draw validation data.

Before result reservation, atomically create and fsync a stable `docs/reviews/step6a2/<full-manifest-sha>/<phase>.claim` with `O_CREAT|O_EXCL`; fsync its parent directory. Its path is independent of code commit, so two launches cannot both claim the same manifest/phase. It records manifest hash, phase, reviewed protected hashes, invocation commit, attempt ID and UTC time and is never removed or rewritten by this workflow. Any existing claim, including one whose result is truncated or missing, refuses an automatic retry; do not rely on parsing a possibly damaged result to discover prior attempts. A reviewed new attempt after failure needs an explicit later protocol/attempt decision; this plan does not add an override. Validation after any observed validation result requires a new reviewed protocol/version and seeds, as in the parent plan.

## Slice 2 — complete counts, parity and decisions

Process manifest cells in ID order, exact chunks of 256 and declared final remainder, preserving component stream shapes and call order. Count generated, evaluated, emitted, and every refusal separately per cell/metric. Record attempted chunk and unfinished IDs on failure because a component array may have been drawn before a paired vector is evaluated. Duplicate or omitted cell/replicate/metric IDs invalidate the attempt; never regenerate a refusal.

Implement pure phase summaries for raw, win and paired synthetic excess. Conditional coverage and each tail use emitted `n`; emission and joint emission-plus-coverage use all generated `R`. Apply five one-sided CP checks and frozen unique families 675/555. Verify fixed-cell eligibility against the predeclared deterministic manifest masks and dynamic-H support against its all-candidate structural proof. Never create an observed-outcome-dependent eligibility mask: that would invalidate the frozen family size. Only the first calibration-passing floor can be selected. Validation tests that one floor once and cannot search another. Statistical failure is a complete verdict only after all required observations are counted; generator, parity, provenance or resource failure is an incomplete/invalid attempt.

During the counted phase, audit the 128 predeclared IDs per cell/phase plus every non-finite, zero, near-zero or t-critical boundary. Compare batch/scalar refusal status, mean, CR2 variance, nu, sample variance, design effect, effective N, and exact coverage/tail decision under the parent plan's scale-aware tolerances. Expose these diagnostic moments only inside the offline runner. Dense-oracle and hand cases remain deterministic tests. Keep report-only CR1 separate; it never rescues a failing candidate.

## Slice 3 — immutable evidence and validation binding

After the stable claim, reserve one result JSON path `docs/reviews/step6a2/<full-manifest-sha>/<phase>-<harness-commit>-<phase>.json` (`<attempt-id>` is commit SHA plus phase) with `O_CREAT|O_EXCL`, and fsync its parent directory. Write a canonical header, append chunk records, then a terminal summary with `UNVERIFIED` or `INCOMPLETE` state and JSON closure through that one handle; fsync checkpoints and closure. A crash may leave invalid JSON, but neither it nor a caught-failure result is replaced, resumed, truncated or accepted. After closing and fsyncing, reopen the result by a validated handle, strictly parse and independently verify all bytes and event partitions, then atomically create/fsync a separate `<phase>.seal` with `O_CREAT|O_EXCL` containing the result SHA-256, attempt identity and `COMPLETE` verdict. Only the immutable claim + result bytes + seal together mean complete. The seal is a control sidecar, not a second result; no `COMPLETE` flag is written into the result before verification. Fsync the containing directory after claim, result and seal creation.

Freeze an exact result schema/key set before implementation: phase seed and complete cell definitions/targets; manifest, harness, estimator, dependency and reviewed/invocation commit hashes; each cell/metric's sorted generated/emitted/refusal reason+ID lists, lower/upper miss IDs and joint-success IDs; all five numeric CP bounds and verdicts; selected floor, first-passing candidate table, report-only CR1, parity audit IDs/values, start/end UTC, elapsed, sampled/OS peak memory and resource verdict. Derive all aggregates from disjoint, duplicate-free event-ID lists: generated partitions into emitted plus typed refusals, emitted partitions into coverage plus both tails, and joint IDs equal emitted intersection coverage. Verify every ID is in its declared cell/range and every required cell/metric is present. Counts, CP bounds and verdicts are recomputed, never trusted from summary booleans.

For validation, require exact deterministic calibration claim/result/seal paths under the full-manifest-hash directory. Open the result using a platform-secure regular-file handle that rejects symlinks/reparse points; fail closed if this cannot be guaranteed. Read the bytes once from that handle, hash and strictly parse them (duplicate keys, trailing bytes and noncanonical encodings rejected), retain/verify file identity through validation reservation, and compare the seal's digest to those same bytes. Independently recompute provenance, event partitions, all numeric CP bounds/checks, deterministic support, first-passing selection, refusal controls and parity completion. If a separate selection artifact exists, its hash/candidate must agree with the verified bytes. Only then atomically claim and reserve validation and create its context. A false flag, syntactically valid but unrelated SHA, incomplete file, omitted cell, duplicate ID, changed target or changed protected code cannot unlock the seed.

## Slice 4 — bounded CLI and final gate

Add `calibrate` and `validate <calibration-result-path>` commands with no seed/count/threshold/floor/resume overrides. Verify installed Python, NumPy, SciPy and psutil versions. Before each allocation, check current RSS plus all simultaneously live planned arrays/cache against 2 GiB and enforce an OS-level process memory limit where available; fail closed if a hard 2 GiB cap cannot be installed. Monitor Windows `peak_wset` (or the platform's verified peak equivalent) as well as current RSS immediately after the largest allocation and at every chunk boundary; stop on either limit. Use a monotonic 2-hour deadline checked inside long generation/evaluation/parity loops and at chunk boundaries. Stream counts and bounded component chunks; do not retain per-replicate vectors across chunks. The counted provider must not share Task 2's fixture stream cache. Keep the clean-tree allowance to user-owned `AGENTS.md` and the exact claim/result/seal paths derived for the current run; any other dirty or untracked entry refuses, and the frozen manifest is not silently edited.

Test exclusivity/concurrent launch, stale/truncated artifacts, duplicate run across commits, wrong-phase/closed context, calibration failure, validation failure without retry/floor search, hash and count tampering, resource cutoff, and caught/abrupt interruption. Tests use scripted outcomes, sentinel RNG providers or the separate fixture seed; never draw either frozen phase seed. Verify full unit suite, portfolio characterization, Ruff check/format, mypy, and `git diff --check`; independent reviewers must inspect the exact code and refusal paths. Record their verdict before any first counted calibration invocation. If any blocker remains, leave inference disabled and do not run the experiment.
