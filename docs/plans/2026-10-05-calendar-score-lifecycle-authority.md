## Task2: separate reviewer process, private channels and release once

The trusted test launcher is a reviewer-role harness in the test module, not a coordinator factory. Before spawning coordinator it creates two distinct duplex Pipe connections and private bootstrap/completion pipes; it transfers only coordinator endpoint and coordinator authentication secret to that child. Reviewer approval endpoint and distinct secret remain solely with reviewer-role launcher; service endpoints remain closed to coordinator. Coordinator exclusively reserves, sends only durable reservation digest/bindings to launcher through its control pipe, and blocks. Launcher rereads/rechecks reservation and source before starting reviewer service or reading fixed validation key. Service receives only its own endpoints and bootstrap after reservation; launcher keeps its reviewer endpoint. No coordinator callable returns/creates reviewer endpoint/secret. Each unused endpoint is closed in every role immediately after spawn.

- [ ] Write RED real spawn tests that stop before reservation, kill reviewer immediately after seal/before claim, kill coordinator, close either IPC endpoint and attempt fresh directories/session restart. Verify the same fixture case stays exhausted and no validation key is released.
- [ ] Write RED authenticated cross-role tests: coordinator submits approve through coordinator channel with valid coordinator secret; forged/copied/rehashed disk approval; wrong session/PID/source/commitment; duplicate approval/release; oversized, duplicate-key, wrong-type and sequence-replayed frames. Authentication uses fresh32-byte secrets and HMAC-SHA256 over bounded canonical frames including schema, role, sequence, session, challenge, both PID+creation identities, source/resource binding and request body. Neither secret enters argv/environment/log/disk; coordinator never receives reviewer secret. Connection.recv_bytes uses MAX_RECORD bound; no recv/pickle of untrusted message payloads. Exact frame schema and monotone per-channel sequence prevent copied requests.
- [ ] Service registers one coordinator identity from bootstrap and validates live PID+creation time, session, reservation digest, source/resource manifest and fixture domain before seal. Every poll/request rechecks peer lifetime and current source/resource identity; poll interval <=.25s, bounded service memory/messages and no detached process. - [ ] Approval-channel request binds complete immutable EvidenceBinding, primary verification digest and independently reviewed all-path receipt digest, source review identifier and fixture decision. - [ ] Coordinator-local completion/verification token object identities never travel as service authority. Service requires its own live approved state from that channel, current coordinator/service lifetime, reserved attempt/session, exact commitment and FIXTURE_ACCEPTED decision; a serialized handle/nonce, coordinator HMAC or saved approval cannot replace any requirement.
