## Command boundary

- Add one `run-counted` command with no user-selected seed, phase, floor or evidence path. Native Windows and unproved platforms refuse before context, claim, cache or RNG. The existing `preflight` and `validate-selection` commands keep their current behavior.
- Start calibration's one monotonic two-hour deadline before deterministic preflight and claim creation. Use the native Linux operations and existing reviewed-commit attestation, Git cleanliness, filesystem and 2 GiB guards. Derive every artifact path from the authenticated manifest and reviewed commit.
- Orchestrate exactly: start calibration → write a result → call `_complete_phase` directly after a successful writer return. Completion performs fresh independent result verification, writes an inert candidate and issues live permission. A writer exception, including one that leaves canonical `INCOMPLETE` evidence, goes directly to cleanup and never to completion. A complete FAILED calibration result ends without validation. A PASSED result enters `_begin_validation_phase`, consuming that exact live permission once and freshly reverifying the trio; then write and complete exactly one validation result at the bound floor.
- Keep all contexts in explicit ownership. Close them once on success and every failure, surface close failures, and never delete, rename, truncate, retry, resume or redraw reserved evidence. A post-claim failure leaves reserved bytes and no permission to continue. Print a final report only after required cleanup succeeds, containing derived artifact paths and complete verdicts but no accepted product threshold. Exit 0 for a complete run (including a statistical FAILED verdict), 1 for operational failure, and argparse's 2 for invalid arguments. A close failure is operational failure with no success report or next phase.
